# 必需资料等待与启动恢复

发现：main原先直接await目录fetch/json，再await实际街区fetch/json，没有截止时间。响应头或响应体永久挂起会让王城、显式旧街区和入口样板都停在加载遮罩，没有简化材质按钮（它在布局准备好后才出现）。三角色展示已使用有限模型加载器，具备5分钟下载+完整字节后2分钟解码预算；但原catch只换失败文字，没有遮罩内恢复入口。

## 最小处理

- `createStartupJsonLoader`复用现有`createAssetLoader`，不引入新加载框架。每份目录/布局JSON从下载到完整response.json解析共享现有5分钟网络预算；HTTP失败/JSON错误明确失败，取消/超时用AbortController中止网络，不返回空布局。响应头返回和body完成后都检查signal，晚到旧响应既不能读入新场景，也不能替换较新重试成功缓存。
- 两份资料顺序加载，各自有预算；不将总启动时间宣称为只有5分钟。有效JSON仍经过原selectStreet/compileTown/compileRoyalLayout约束，编译失败进入同一恢复页，不把不合格内容当成功。
- `waitForStartup`给当前等待加“停止等待”，并在pagehide取消；finally移除按钮和两项临时监听。王城/旧街区/样板用于目录和布局阶段；三角色展示用于原模型等待。主场景PNG仍沿用已有“先用简化材质进入”和失败重试，GLB仍是非阻塞替身；未改变已有5/2分钟模型约定。
- `showStartupFailure`统一四个入口的失败反馈：区分超时、主动停止、无法解析及普通失败，提供“重新载入当前页面”和“返回王城入口”。重新载入调用location.reload，保持显式街区/角色/样板查询，避免半初始化场景内再次创建渲染器或监听。只处理反馈DOM，不访问/修改localStorage，不恢复/重置邮路；入口返回是普通整页导航。
- 恢复按钮最小44px、恢复页限宽/可滚动，焦点到重新载入；模型替身不冒充可完成任务。退出/重新载入时已接受资源仍由页面生命周期负责，原生解码不可强行终止的边界不变。

## 定向测试

6项新测试通过：挂起响应头超时/abort/迟到不读body；挂起body仍有预算/晚到不提交；HTTP和格式失败可再次请求而非供应空布局；主动停止及成功时临时按钮/监听清理；pagehide取消；恢复文案/单次原URL重载且不访问存档。均用可控Promise和假时钟，不实际等待5分钟。已加入test:assets；本段未重复中期117项聚合或正式build。

## 浏览器最小复查与剩余边界

在可用故障模拟条件下，仅需：一份目录或布局延迟时“停止等待”→恢复页→重载当前链接，确认旧进度保留；一份JSON请求失败或坏JSON的恢复页；一张角色展示取消或加载失败后的恢复操作。正常入口/三展示此前已QA通过，但本段取消按钮、恢复页和样式尚未浏览器验证。若现有Chrome工具不能注入网络故障，明确记录未测，不以测试模型代替实际浏览器。

脚本自身或CSS模块无法下载时，本段JS不会运行，不能靠它保证恢复页出现；同步JSON.parse或布局编译若阻塞主线程，计时器也不能抢占它。当前JSON是本地小体积静态文件，未引入Worker、解析尺寸框架、自动重试或备用资料。浏览器关闭或进入后台可能延迟定时器执行；恢复到可运行的事件循环后才能展示超时结果。真实慢网、Safari行为及原生永久解码内部回收仍没有实机证明。
