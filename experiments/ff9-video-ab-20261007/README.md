# FF9 视频 A/B · 2026-10-07

目标：验证已有 3D 角色与布景能否作为视频模型的输入，以及首帧美术润色是否值得加入生产链路。

## 结果

- A：Three.js 原始首帧 → MiniMax H3 FL2VA。
- B：同一首帧 → Qwen-Image-2.1 润色 → 相同 MiniMax H3 FL2VA。
- 每条展示版为 864×480、24fps、120 帧、5 秒、静音；未裁画面。原始视频为 124 帧 / 5.1667 秒，保留模型原生音轨。
- 同步预览：`http://127.0.0.1:5209/experiments/ff9-video-ab-20261007/compare.html`。
- 双画面合并：`AB-side-by-side.mp4`，左 A 右 B。

## 固定条件

同一视频模型、同一 Turbo8 LoRA、同一提示词、种子 14027、8 步、res_multistep/simple、分辨率与时长。实际 Comfy 图已保留，`parameter-verification.json` 确认只存在首帧路径和输出文件名前缀差异。没有添加其他风格 LoRA。

首帧构图用相同的已验收莫古利 GLB、售票亭、海报、王城和树生成。捕获入口 `ff-video-frame.html` / `src/ff-video-frame.js`，无 UI、固定机位与角色 Idle 姿态。此入口只用于本地实验，不修改游戏中的角色位置。

## 单次观察

A 保持原来的简化 3D 质感和角色外形；B 增加木材、毛绒与远景的细节，整体更暖、更偏复古棕色，接近插画式成片。两条里莫古利均做了小幅挥手，场景未突然切换或增加角色。B 的脸部比例略有变化，推近后脚部更加贴近画面边缘。

这是单镜头、单种子的结果，不能据此认定所有镜头都稳定或已经达到原作 FF9 美术。下一轮可让初始机位更宽松，并将 B 的色调拉回我们明亮、好逛的乐园目标；不必先训练新的场景模型。

## 失败与修正

第一次 B 润色用了 denoise=0.65，结果成为重复小图案，已保存在 `B-polish-failed-low-denoise.png`，未用于 B 视频。实读 ComfyUI `TextEncodeQwenImage21` 节点确认：输出 latent 是空潜变量，参考图只作为 conditioning；低 denoise 并不等同于对原图进行低幅重绘。

修正为官方式完整采样 denoise=1.0，保留同一原图、提示词、种子与 25 步；得到保持人物和布景的 B 首帧。共执行两次图片任务和两次视频任务，没有另行挑选多条视频。

## 资源与时间

复用 4090 上现有空闲 ComfyUI GPU0 / 8188，所有任务串行。没有启动/停止共享服务、下载新模型或训练。

模型任务墙钟时间（包含加载与采样）：失败润色 12.3 秒、修正润色 8.3 秒、A 视频 96.1 秒、B 视频 99.1 秒，合计约 216 秒。它不是 GPU 利用率积分或账号账单。

原始提示词、计划、工作流、任务回执、媒体参数与截图均留在本目录。Qwen 润色检查后才用于 B 视频；失败样本如实保留。
